1. Overview and specs

The KM003C is the successor to the KM002C. ChargerLAB says the KM002C "was discontinued due to the shortage of chips" S1. The KM003C is an in-line USB-C power meter and PD analyzer/trigger. It has a USB-C plug, a USB-C receptacle and a third USB-C port labelled "HID", which powers the unit and connects it to a PC O S1 S2 S6.

Known hardware quirks

  • USB 2.0 passthrough. The FAQ says some USB 2.0 devices "(Like mouse, keyboard)" fail through the tester: "It is a hardware issue ... the internal module has affected the USB2.0 devices. The USB3.0, USB3.1, USB3.2 and USB4 devices can work normally." O S4. AnandTech also says ChargerLAB acknowledged this as a hardware design bug 3P S20.
  • Plug solder joints. A hobbyist teardown found that the solder joints of the male plug's top-side pins lift from the PCB. A unit made in 2023-11 had extra solder added at that spot 3P S17.
  • PD3.2. The product page now says "This tester is the latest version and can support PD3.2" O S3. PD 3.2 features arrived through firmware and PC-software updates (see §5). I found no evidence of a hardware revision for PD3.2 I.

Offline (stand-alone) recording

  • The unit records V/I/capacity/energy to its 4 MB flash without a PC. The PC software reads and exports the records O S2 S7.
  • Up to 40 record groups. Each group holds at most 10,000 points. The save interval is 1–120 s (5 s gives about 13 h). Auto start and stop can trigger on a current threshold O S2. The 2024 chart says "Group Number for Offline Recording: 15-40" O S5.
  • Firmware V2.0.0 "Optimized offline curve logging". V2.0.1 and V2.0.6 fixed offline-reading bugs O S8 S9.

5. Protocol detection and PD features

Auto-detection (KM003C), from the manual: PD2.0 / PD2.0 PPS / PD3.1 (EPR) / QC2.0 / QC3.0 / QC3+ / QC4+ / QC5 / AFC / FCP / SCP / VIFC / UFCS / APPLE2.4A / SAMSUNG / VOOC / MTK PE / SFCP / TFCP O S2. MTK-PE, VOOC and SVOOC detection is "thanks to built-in load" and is KM003C-only O S1 S2. The 2024 article's list also names SVOOC O S6.

Trigger, on-device ("Application → Charging protocol"): PD2.0 / PPS / EPR / QC2.0 / QC3.0 / AFC / FCP / SCP / VIFC / UFCS / VOOC. VOOC/SVOOC needs the original cable and a small load. MTK PE and SFCP cannot be triggered O S2 S6.

Trigger from PC (firmware ≥1.7.9 with PC 2.3.0): PD (up to 28 V 5 A shown), UFCS, QC2.0/3.0, FCP, SCP, AFC, VFCP, SFCP O S13. ChargerLAB also documents triggering over the CDC virtual serial port in "KM003C/002C Protocol Trigger by Virtual Serial Port (Instructions)". The manual and FAQ name this document O S2 S4. I read it from the community-hosted copy (S18 docs/official/); §6 summarizes it.

PD features

  • PD protocol analyzer / packet capture. It was added in firmware 1.2.4 and PC 2.0.3. It captures SOP/SOP'/SOP'' packets. The manual says the PC analyzer holds "up to 10,000 pieces of data" O S2.
  • UFCS protocol analyzer (FW 1.7.1, PC 2.2) and UFCS 1.2 capture (PC 2.5.0) O S2.
  • PD 3.2: SPR AVS added in FW 1.9.2. PD 3.2 packet capture came in PC 2.5.0, and PD 3.2 identification on the Dashboard in FW 2.0.7 O S2 S8.
  • EPR / PD3.1: supported throughout. A 240 W cable is needed for EPR unless cable simulation is used O S2.
  • Cable simulation (decoy e-marker). The tester can "simulate a 50V/5A cable". Since FW 1.9.7 the default is 50 V 5 A (240 W, EPR) O S2 S9.
  • PDM application. FW 2.0.5 "Added support for sending and receiving custom PD data through the PDM application" O S9.
  • eMarker reader. Reads 3A/5A/50V/EPR/TBT3/TBT4 cables, and Thunderbolt 5 since FW 1.9.3. The eMarker IC model has been identified since FW 2.0.0 (HUSB332x, CPS8825/8826, WAYON and others) O S2 S8 S9.
  • Apple charger SN reading. Apple device model and Huawei power-bank battery display arrived in FW 2.0.0 O S6 S9.
  • The Dashboard shows a "possible" protocol from D+/D− voltage levels. The manual includes a D+/D− voltage → protocol table O S2.

6. Software, SDK and USB interfaces

PC software

  • "POWER-Z" PC software, V2.x. It is Windows-only in practice.
    • The executable is Mtools. Gigazine installs "Mtools" from "(V2.3.0) PE version - PC Software (KM002C/KM003C).zip" 3P S21, and the community found it is a Qt5 x64 app, Mtools.exe C S18.
    • Latest version per the manual: V2.5.1 (2026-04-16) O S2.
    • Functions: real-time curves, recording (CSV / SQLite .db export), PD/UFCS analyzer, protocol trigger, firmware update, and many testers at once O S6 S7.
    • The FAQ says it supports "Windows 10 or later". PC 2.2.1 "Integrate[d] the support of Windows 7" O S2 S4. AnandTech: "The KM003C supports only Windows officially" 3P S20.
  • POWER-Z Lab V3.0 Beta (2025-03-19). Windows 7/10/11 and macOS, distributed via a Telegram link.
    • It requires tester firmware 2.0.0, and its recordings are .pzd files.
    • Known bugs: no offline-data viewing on Mac, and FW 2.0.0 cannot read eMarkers.
    • As of March 2025, ChargerLAB recommended "the more stable and feature-complete V2.4.0" for most users O S10.
    • The "2.0.0" bundled with this 2025 beta predates the public V2.0.0 changelog entry (2026-03-26) by a year, and that entry adds eMarker IC reading. It is probably a different pre-release build I.
  • Firmware updates run through the PC app, which "will erase the old firmware and write the new one". The files are .mencrypt O S8 S10. The community reports the format is AES-128-ECB encrypted Qt-serialized metadata plus the image, with the application at flash 0x4000 C S18.

Official API / SDK

  • FAQ: "Are there any open APIs available for further self-development? ... We currently only provide limited toolkit for reference." It links hiddemo_vs2019_for KM002C&3C and names a "Protocol Trigger by Virtual Serial Port" document O S4. The manual's feature list still says "Provide open API" O S2.
  • hiddemo_vs2019_for-KM002C3C.zip O S14 contains a C++ libusb-1.0 demo (hiddemo.cpp) and a Chinese spec, KM002C&3C API Description.docx, titled "Km002c接口说明" (KM002C interface description).
    • The demo opens VID 0x5FC9 with PID argument 0x0000, which matches any PID, so it does not confirm 0x0063. A commented-out line uses PID 0x0061. The demo also counts devices with VID 0x5558 (purpose unknown).
    • It claims every interface and treats interrupt endpoints as "HID" and bulk endpoints as "user". It polls CMD_GET_DATA with ATT_ADC every 150 ms.
    • AnandTech sent the same GET_DATA/ADC command word (0x0C000200) from Python/pyusb on EP 0x01 and read the reply on 0x81. It also sent the command as a string over the Windows COM port. It found that the ID byte "could be varied from 0x0 to 0xFF without any loss in functionality" 3P S20.
  • Virtual serial port (CDC) text commands. This is official and requires FW ≥1.7.9 per S2. Commands are plain-text lines for the protocol-trigger ("PDM") module O (copy at S18 docs/official/KM003C_002C Protocol Trigger by Virtual Serial Port (Instructions).docx):
    • pdm open / pdm close
    • pdm set type=?,em=?, where em is cable simulation: 0 off, 1 20V5A, 2 50V5A EPR
    • entry pd|ufcs|qc|fcp|scp|afc|vfcp|sfcp
    • pd pdo, pd req=?,volt=?,cur=? (PPS/AVS), pd cmd=?, pd data=… (raw SOP + header + data)
    • qc 9V, qc3 volt=…, ufcs req=…, and similar
    • reset
    "Virtual serial port does not need to set Baud". Windows 10/11 needs no driver; Windows 7 needs the driver listed above.
  • No official SDK or library beyond this. ChargerLAB acknowledges the community Linux driver: "Some enthusiasts developed a 'HWMON POWER-Z driver' for linux, but we are not responsible..." O S4.
  • Linux kernel powerz hwmon driver (author Thomas Weißschuh). Supported chip: "ChargerLAB POWER-Z KM003C". It "communicates with the custom protocol over USB" and exposes channels named as on the device and PC software 3P S16. The patch was posted in September 2023. The driver's page exists in the kernel.org docs for v6.7 but not v6.6, which suggests it first shipped in Linux 6.7 3P S16 I.
  • Community implementations: km003c-protocol-research (Python + Rust parser, protocol spec, USB captures) and km003c-rs C S18. There is also a custom Rust firmware for HW2.1 C S19.

USB interfaces

Official: the API description docx O S14 (translated) says the device offers three interfaces with one command set:

  1. USER: called WinUSB on Windows and "USB USER" elsewhere; about 200 KB/s.
  2. CDC virtual serial: baud rate ignored; about 200 KB/s; works with any serial terminal.
  3. HID: needs no driver on any platform; 64-byte packet limit; about 60 KB/s.

The manual summarizes this as "Composite USB port, driver-free" O S2. AnandTech restates the three interfaces ("WinUSB (vendor specific interface) device, a HID device, or a virtual serial port (CDC)"). On their 2023 Ubuntu 20.04 setup only the HID interface was bound (to usbhid), and no /dev/ttyACM0 appeared 3P S20.

Naming caution: in ChargerLAB documents, "HID" is also the name of the physical USB-C port used for PC and power. "Connect via the HID port" therefore does not mean the PC software uses the HID class O S2 S10.

Endpoint discrepancy: AnandTech wrote that ChargerLAB says commands can also go to "EP 5 OUT and EP 3 OUT ... at addresses 0x5 and 0x3" 3P S20. The community dump puts the CDC data OUT endpoint at 0x02 and has no 0x03 OUT. The firmware may have changed, or one source is wrong; this is unresolved I.

Which interface the official app uses is not documented by ChargerLAB.

  • The community reports that the authenticated AdcQueue streaming (needed for 50/1000 SPS graphs) works only on IF0, the vendor bulk interface. Mtools.exe contains the streaming-authentication routine. HID gives basic ADC and PD access but not authenticated streaming C S18.
  • AnandTech captured the official app's traffic with Wireshark/USBPcap but did not name the interface 3P S20.
  • ChargerLAB ships a driver installer O S4 S15.

Together this suggests the PC app uses the vendor/WinUSB interface (IF0) I.

7. Notes for a CLI client (summary of the above)

  • Use VID 0x5FC9, PID 0x0063 (KM002C is 0x0061) C S18.
  • On Linux, the in-kernel powerz driver claims IF0. Unbind it, or use the hwmon sysfs values 3P S16 C S18.
  • Offer the rate set 2 / 10 / 50 / 1000 SPS as the device-native streaming rates C S18.
    • The manual's dashboard rates "2/10/50/1k Hz" corroborate this set O S2.
    • The official UI's "1 SPS" likely maps to index 0, which is 2 SPS I.
    • Do not advertise 10 kSPS S14 S18.
  • Values arrive in µV / µA (int32; signed current gives direction) O S14.
    • Use the instantaneous fields, not the 1-second *_avg fields, for fast polling 3P S20.
    • Line voltages are in 0.1 mV in the ADC snapshot O S14.
    • In streaming, line-voltage units depend on the rate (community: 0.1 mV at 2 SPS, otherwise 1 mV) C S18.
  • Temperature arrives only in the ADC snapshot, not in the stream C S18. The official app shows it only at 1/10/50 SPS O S2.
  • PD/QC/UFCS triggering can be scripted over the CDC serial port with the official text commands in §6 O.
  • The tester resets if it is powered from the measured VBUS and VBUS drops to vSafe0V. Power it from the HID port 3P KM002C S22; O S2.
