powerz CLI reference

Read-only command-line client for the ChargerLAB POWER-Z KM003C (USB 5fc9:0063). Built for humans at a terminal and for AI agents and scripts: JSON on stdout, fixed output shapes, structured errors with stable exit codes, and a self-describing powerz schema. The authoritative, machine-readable version of this page is powerz schema; a test keeps it identical to the real output.

1. Build and connect

# macOS
brew install libusb pkgconf
# Debian/Ubuntu
sudo apt install libusb-1.0-0-dev pkg-config

go install github.com/ljagiello/gopower-z/cmd/powerz@latest

Connect the meter's USB-C port marked HID to the computer. Plug the source (charger) into the meter's female receptacle and the device under test onto its male plug. On macOS no driver or root is needed. On Linux, the in-kernel powerz hwmon driver owns the interface; powerz detaches it while running, and you need a udev rule granting access to 5fc9:0063 (otherwise exit code 6). Linux is built and unit-tested in CI but has not yet been run with a meter attached.

2. Quick start

# dashboard on a terminal, one JSON reading when piped
powerz

# one snapshot
powerz read

# min/mean/max, energy, charge, USB-PD capture
powerz measure --duration 10s

# model, firmware, serial, settings
powerz info

# decoded USB-PD traffic, then a summary line
powerz pd --duration 30s

# one minute of snapshots, two per second, saved as CSV
powerz log --duration 1m --interval 500ms --format csv > run.csv

# the machine-readable reference
powerz schema

3. Agent contract

  • JSON whenever stdout is not a terminal (force it with --json, or text with --text). stdout carries data only; diagnostics and errors go to stderr.
  • Fixed shapes. Every documented key is always present. Unavailable values are null and empty lists are []. Every object carries schema_version (currently 1).
  • Units are in field names: _v, _a, _w, _wh, _mah, _c, _s, _ms, _uv, _ua, _sps, _percent.
  • Timestamps are UTC ISO 8601 with milliseconds: 2026-11-17T01:34:25.627Z.
  • Direction. Current and power are positive when flowing from the meter's female receptacle to its male plug, which is the normal set-up and matches the meter's screen. direction says so explicitly (receptacle_to_plug, plug_to_receptacle or none), and raw.ibus_ua keeps the meter's own signed value.
  • Errors are one JSON object on stderr with code, exit_code, retryable and an actionable hint.
  • A non-zero exit can still carry data. measure prints its object and pd its summary line when they end early: on SIGINT/SIGTERM (exit 130, "end_reason":"interrupted", which is what an agent harness timeout sends) or when the meter disappears, is taken by another program or cannot be drained (exit 3, 4 or 1, "end_reason":"error"). log lines already printed stay valid. Read stdout before discarding it.
  • Bounded. read, measure, info, devices and schema terminate on their own. log and pd take --duration, which automation should always set.
  • One process per meter. A concurrent call fails with busy (exit 4, retryable) unless it passes --wait 10s to queue.
  • Validation, not silent changes. Out-of-range values such as --interval 5ms are usage errors that state the limit.
  • Interpretations are separate. Fields under inferred are computed by powerz, not reported by the meter.
  • Unknown is not the same as empty. Firmware-dependent fields are decoded only for firmware 1.7.9 to 2.0.7, the versions that were analysed. For any other firmware, or when the version cannot be read (firmware_error says why), they are null, raw.tail_layout is unknown and inferred.dashboard_classifier is null. A null dashboard label with a non-null classifier means the screen shows [N/A].

4. Commands

CommandOutputFlagsPurpose
readone JSON object-One snapshot. Default command when stdout is not a terminal. Reads the firmware version first (CONNECT plus one MemoryRead) to decode the firmware-dependent fields.
measureone JSON object--duration 5s --interval 100ms (≥ 20 ms) --pd=true --bin 0 (automatic)Samples for a fixed time. Returns stats (min/mean/max/last, stdev and p5/p50/p95 of V, A, W, °C, D+ and D−), bins (the window over time, see below), energy and charge over integrated_s, the dominant direction, and the USB-PD capture with every record. end_reason says whether the window completed or ended early. The main command for agents.
logJSON lines or CSV--interval 200ms (≥ 20 ms) --format jsonl|csv --count/-n --durationStreams snapshots (same shape as read). CSV columns: time, vbus_v, ibus_a, power_w, direction, vbus_avg_v, ibus_avg_a, power_avg_w, temp_c, cc1_v, cc2_v, dp_v, dm_v, vdd_v.
pdJSON lines--interval 25ms (≥ 10 ms) --duration --count/-n --goodcrcOne record per captured USB-PD message or event, then a final "kind":"summary" line with counts, capabilities, contract, end_reason and a note when nothing was captured. Bytes the meter delivered that cannot be parsed are kept as "kind":"undecoded" records. Sends only GET_DATA for the PD buffer: no session and no memory reads.
infoone JSON object-USB descriptors; model, firmware and hardware versions (ISO dates), serial and UUID; settings (sample rate, name, brightness, raw codes). The identity comes from three memory blocks: a block that cannot be read leaves only its fields null and is listed in errors (exit 7).
devicesone JSON object-Lists connected meters without claiming them, so it works while another process holds the meter.
watchterminal UI--interval 200ms --no-pdLive dashboard for humans; refuses to run without a terminal.
schemaone JSON object-Commands, flags with types and defaults, typed field definitions with nullability, exit codes, verified facts and caveats.
versionone JSON object-Tool and schema version (also --version).
completionshell scriptbash|zsh|fish|powershellShell completion for commands and flags.
helptext-Usage of powerz or of one command (also --help on any command).

Common flags, accepted before or after the command: --json --text --serial S --timeout D (≥ 100 ms) --wait D --trace. Flags take two dashes (--duration 10s or --duration=10s); -n for --count is the only shorthand. A single-dash long flag such as -duration is a usage error whose hint says so.

Captured before the following fields were added. Builds after v0.1.0 add stdev, p5, p50 and p95 to every stats entry, stats.dp_v and stats.dm_v, and the bin_s and bins described next.

Shape over time: bins (after v0.1.0)

Min, mean and max show that the current spanned 134–441 mA, but not when or how: one step partway through, or switching back and forth. bins cuts the window into bin_s slices, each with the min, mean and max of vbus_v, ibus_a and power_w. The width is automatic, chosen when the window ends from the time actually measured (at least 5 polling intervals per bin, at most 120 bins), so a long window stopped early keeps its shape; or it is set with --bin 1s (at least --interval, at most 1000 bins). Illustrative excerpt, computed by powerz with --bin 1s (the automatic width for 60 s would be 0.5 s) from a synthetic 60 s window in which the current steps from 134 to 441 mA at 42.3 s:

  {"t_s": 43, "samples": 10, …, "ibus_a": {"min": 0.43654, "mean": 0.440502, "max": 0.444248}, …},

  • Reading the shape: the step is the first bin whose ibus_a.mean leaves the earlier level; a bin that straddles it (42 s above) has a wide min–max. A burst inside one bin raises that bin's max much more than its mean.
  • Empty bins (the reads in them failed, or were slower than the bin) have samples 0 and null values. The last bin may be shorter, and also holds a reading taken just after the window ends.
  • stdev and percentiles describe the readings in the window (p50 is the median; percentiles interpolate between readings, the R/NumPy default). A few outliers or short bursts leave p5–p95 narrow; they show in max (or min) and in a stdev that is large compared with p95 − p5. A level change shows in the bins, not reliably in these: a step in the middle of the window leaves the mean and p50 equal. Readings close in time repeat at the meter's own sample rate, so do not turn stdev into a confidence interval with √n.
  • D+ and D−: a USB device that drops off the bus usually changes D+ or D−; stats.dp_v/dm_v give their range over the window.
  • Size: measure keeps every reading until the window ends (about 64 bytes each), so a window holds at most 1 000 000 readings (about 28 hours at 100 ms, up to about 150 MB of memory at that limit); longer runs are a usage error that points to log.

Detected level changes (a list of steps and ramps with their times) are planned for a later release.

Text mode (--text) prints current in mA, each mean with its spread, and a sparkline of the whole window (empty bins as gaps).

7. Agent recipes

How much power does the attached device draw?

powerz measure --duration 30s --wait 10s
# .stats.power_w.mean / .max (peak draw), .energy_wh over .integrated_s, .direction

Did the draw change during the window?

powerz measure --duration 60s
# .bins[]      per-bin min/mean/max of vbus_v, ibus_a, power_w over time:
#              a level change is where .ibus_a.mean moves and stays
# .stats.ibus_a.max far above .p95, with a .stdev large next to .p95 - .p5: a few bursts
# .stats.dp_v  D+ range; a USB device dropping off the bus usually moves it

What does this charger offer, and what did the device negotiate?

USB-PD is only exchanged when the device attaches or renegotiates, so start the capture first and connect the device during it:

powerz measure --duration 20s
# .pd.source_capabilities[]  offered PDOs (fixed/PPS/AVS: volts, amps, watts)
# .pd.contract               the Request the source accepted and confirmed with PS_RDY
# .pd.note                   set when nothing was captured
# .last.inferred.dashboard_label*  the meter's D+/D- protocol labels

Handling failures

  • Exit 4 or 5: retry; pass --wait 10s to avoid exit 4.
  • Exit 3: ask the human to connect the meter (data port to the computer).
  • Exit 7: the JSON on stdout is valid; check failed_samples, last_error or errors.
  • Exit 130, 3, 4 or 1 from measure or pd: stdout may still hold a result for the part of the window that was captured; end_reason tells.
  • Never run two powerz commands against one meter in parallel.

8. Safety model

Every frame is checked against a whitelist (hardware/km003c/guard.go) right before it goes to the device. A fuzz test proves the whitelist accepts exactly these frames and nothing else:

  • GET_DATA for ADC, settings and the PD buffer (powerz uses only the vendor bulk interface; the HID and CDC interfaces are never opened);
  • CONNECT and DISCONNECT;
  • MemoryRead of exactly three fixed 64-byte information blocks.

Never sent: settings writes, factory reset, firmware/DFU commands, authentication, stream control, and the CDC text commands that make a charger raise VBUS. powerz cannot change the voltage on the bus. Ending each session with DISCONNECT means the meter does not queue an unsolicited frame for the next program.

Stall hazard: the meter stalls, and its watchdog reboots it, if a request arrives while an earlier reply or zero-length packet is still queued. powerz matches replies by transaction id, consumes the ZLP after MemoryRead data, and drains the endpoint after any failed exchange, after an idle gap and before closing. Fake-meter regression tests and fuzzing cover these paths.

9. Verified and caveats

  • Verified on firmware 1.9.5 under a 0.44 A load: VBUS, current, power, CC and D+/D− match the meter's screen. Positive current means receptacle → plug, and the screen's arrow agrees. The dashboard labels ([N/A] / VOOC) match the screen.
  • USB-PD decoding follows the USB-PD 3.1 specification and is fuzzed, but has not yet been checked against a live negotiation.
  • Sniffed protocol sessions (AFC/FCP/SCP/UFCS/VOOC sessions the meter detects) live only in firmware RAM and are not exposed over USB.
  • Polling rate: the meter samples at its configured rate (see info); polling faster repeats values.
  • PD buffer: reading PD drains the meter's buffer, so only one consumer sees each record.
  • Firmware newer than 2.0.7 is not guessed: its firmware-dependent fields and dashboard labels are reported as unknown until that firmware has been analysed.
